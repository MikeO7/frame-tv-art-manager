## 2026-06-08 - Safe error handling assertion with strings.Contains
**Learning:** Go evaluates `||` conditions sequentially, allowing tests to safely check `err == nil || !strings.Contains(err.Error(), "foo")`. If `err` is nil, the first half evaluates to true, short-circuiting the second half and safely avoiding a nil pointer panic without requiring nested `if err == nil { t.Fatal... }` boilerplate.
**Action:** Use this compact short-circuit assertion pattern to concisely write unit tests for error pathways where you expect an error with a specific message.
## 2026-07-03 - Context cancellation during wait group blocking loops
**Learning:** Testing `case <-ctx.Done():` inside a tight bounded worker loop running over a channel (where no blocking operations happen inside the loop itself) is tricky. If you cancel the context and pass an empty channel, the loop never enters. If you pass a populated channel, the fast path might process items so fast it drains the channel before the context cancellation takes effect. Providing a heavily buffered channel with many mock jobs, immediately invoking `cancel()`, and ensuring `handleSingleOptimization` (the worker function) has dummy data helps guarantee a worker gets stuck in the `select` statement loop long enough to catch the cancellation.
**Action:** When mapping untested `<-ctx.Done()` pathways inside loops pulling from channels, prime the channel with excess dummy jobs and cancel the context *before* invoking the worker runner.
