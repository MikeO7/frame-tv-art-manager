Docker and NAS setup

Run Frame TV Art Manager with Docker on a NAS or home server

Short answer: run the ghcr.io/mikeo7/frame-tv-art-manager:latest image with your Samsung Frame TV’s IP address in TV_IPS and a ./data:/data volume. Approve the connection once on the TV, then copy JPEG or PNG files into data/artwork. The image runs on amd64, arm64, and armv7, so it fits a Synology or Unraid box, a mini PC, a Raspberry Pi-class board, or a Mac.

Docker Compose is the easiest way to keep Frame TV Art Manager running around the clock. The container holds the service; a data folder next to it holds your art, the TV’s pairing token, and the record of what it uploaded to each TV.

What do I need before installing?

  • A Samsung Frame TV running Tizen 8.0 or newer, on your home network. Other firmware may work, but Samsung’s private Art Mode protocol varies.
  • An always-on machine on the same network with Docker and Docker Compose.
  • Access to your router, to give the TV a fixed IP address.
  • The TV switched on and in reach of its remote for the one-time approval.

Port 8080 serves the health and status pages. It doesn’t accept uploads unless you turn the uploader on (see below).

How do I install it, step by step?

  1. Give the TV a fixed IP address. In your router, create a DHCP reservation so the Frame TV always gets the same IP address. You can find the TV’s current address in its network settings.
  2. Create the compose file. Make a folder for the service, save the compose.yaml above inside it, and replace 192.168.1.150 with your TV’s address.
  3. Start the container. Run docker compose up -d in that folder, then docker compose logs -f frame-tv-art-manager to watch it connect.
  4. Approve the connection on the TV. With the TV switched on, an Allow/Deny prompt named “Frame Art Manager” appears. Choose Allow with the remote. This happens only once.
  5. Add pictures. Copy .jpg, .jpeg, or .png files into the data/artwork folder. They are prepared and uploaded on the next sync.
  6. Check that it worked. Open http://SERVER-IP:8080/status in a browser. Your TV should be listed with status ok, and the pictures appear in Art Mode on the TV.

The first sync runs as soon as the container starts and then every 30 minutes. To pick up new pictures sooner, restart the container or lower SYNC_INTERVAL_MINUTES.

Keep your originals elsewhere. With image preparation on (the default), each picture in data/artwork is replaced by its 3840×2160 version and may be renamed. Copy pictures in; don’t move your only copies.

What is stored in the data folder?

Folders inside the /data volume
FolderWhat’s in itIf you lose it
/data/artworkYour art collection, plus a hidden .frame-tv-art-manager folder that tracks itThe TV keeps what it has, but there’s nothing left to sync.
/data/tokensEach TV’s pairing token and the record of which pieces Frame TV Art Manager uploadedYou approve the TV again, and art it uploaded earlier looks like art you added yourself, so it won’t be cleaned up or rotated automatically.

Mount the whole /data folder, as in the example, and both survive container updates. Pairing tokens and state files are saved readable only by their owner (mode 0600). Art files are readable by others (0644) so you can browse them over SMB or NFS.

Does the container need host networking?

No. Frame TV Art Manager connects out to the TV’s IP address, so normal bridge networking works. The only requirement is that the machine can reach the TV. If your TV is on a separate VLAN or IoT network, your firewall has to allow the connection.

The service doesn’t need inbound access from the internet. Keep port 8080 on your home network.

Notes for Synology, Unraid, Raspberry Pi, and Mac

Synology

On DSM 7.2 and later, open Container Manager, create a Project, choose a folder such as /volume1/docker/frame-tv-art-manager, and paste the compose file. The ./data path is then created inside that folder, where you can reach it from File Station or a network share.

Unraid

Use the Docker Compose Manager plugin with the same file, or add the container from the Docker tab: repository ghcr.io/mikeo7/frame-tv-art-manager:latest, a variable TV_IPS, port 8080, and a path mapping from /mnt/user/appdata/frame-tv-art-manager to /data.

Raspberry Pi and other small boards

The image is built for arm64 and armv7, so it runs on 64-bit and 32-bit Raspberry Pi OS. Image preparation is the heaviest job: a 24-megapixel photo needs roughly 250 MB of memory for a second or two, and each picture is limited to 512 MB by default (IMAGE_MAX_WORKING_MEMORY_MB). 8K photos fit within that default.

Mac

Docker Desktop runs the same compose file. Make sure the Mac stays awake, or the sync stops while it sleeps. You can also build and run the binary directly (see Without Docker).

Folder permissions

If the logs show the container can’t write to data, create the folders first with mkdir -p data/artwork data/tokens. The image starts as root so it can set ownership using PUID and PGID (for example PUID=1000, PGID=1000). To run without root, give both folders to your user, set user: "1000:1000" in the compose file, and leave PUID and PGID unset.

How do I check that it’s working?

Four pages on port 8080 tell you how things are going:

  • /live: the process is running.
  • /ready and /health: return 200 once a sync has succeeded, and 503 while starting or after a failed sync. Point an uptime monitor here.
  • /status: details for each TV, including its status, how many pieces it holds, whether it’s in Art Mode, the last error, and rotation progress.

The container’s built-in health check watches /live. Docker doesn’t restart an unhealthy container on its own; restart: unless-stopped covers crashes. Logs are JSON, one line per event, with the TV address, status, and counts of uploads and deletions.

Can I see what it would do without changing anything?

Yes. Set DRY_RUN=true and Frame TV Art Manager reads your folder and the TV and works out its plan, but uploads, deletes, and saves nothing, and it won’t wake the TV. Each TV reports dry-run in /status. A dry run uses an existing pairing, so approve the TV once in normal mode first. The uploader is unavailable during a dry run.

Leave REMOVE_UNKNOWN_IMAGES at its default of false unless you really want Frame TV Art Manager to delete every piece it didn’t upload itself.

How do I update it?

Run docker compose pull and then docker compose up -d. Your art, pairing, and history live in data, so nothing needs to be set up again.

Troubleshooting common problems

The TV never shows the Allow prompt

Make sure the TV is switched on and that TV_IPS matches the address in the TV’s network settings. From the server, check that it can reach the TV, then look at docker compose logs for the connection error.

The TV asks for approval again after a restart

The pairing token isn’t being kept. Check that ./data:/data is mounted and that data/tokens exists and is writable. Changing CLIENT_NAME also makes the TV ask again, so pick a name and keep it.

Status says unreachable

The TV was off, asleep, or not on the network during that sync. Frame TV Art Manager tries again on the next one. To wake a single TV first, set TV_MAC to its network MAC address; Wake-on-LAN is only sent when the TV is known to be off, and it’s disabled when you list more than one TV.

Status says storage full

The TV is out of room. With rotation on (the default), this clears once rotation starts; if it stays, the TV is probably full of art you added yourself. See the storage-full guide.

How do I turn on browser and iPhone uploads?

The uploader is off by default. Set UPLOAD_ENABLED=true and an UPLOAD_TOKEN of at least 16 characters, then open http://SERVER-IP:8080/upload. Sign in with username frame and the token as the password.

Keep it on your home network. Plain HTTP doesn’t encrypt the password or the pictures. Don’t expose port 8080 to the internet; put a TLS reverse proxy in front if you need access from outside.
