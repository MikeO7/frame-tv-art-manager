Docker Compose installation

Run a Samsung Frame TV art manager with Docker

Short answer: deploy the GHCR container with the TV’s local IP in TV_IPS and a persistent /data volume. Approve the first connection on the TV, then add JPEG or PNG files to data/artwork.

Docker Compose is the simplest way to run Frame TV Art Manager continuously on a Linux server, mini PC, or compatible NAS. The container packages the Go service and its image-processing dependencies while the persistent data directory holds artwork, pairing tokens, and reconciliation state.

Minimal Docker Compose configuration

compose.yaml
services:
  frame-tv-art-manager:
    image: ghcr.io/mikeo7/frame-tv-art-manager:latest
    container_name: frame-tv-art-manager
    restart: unless-stopped
    environment:
      TV_IPS: "192.168.1.150"
      CLIENT_NAME: "Frame Art Manager"
    ports:
      - "8080:8080"
    volumes:
      - ./data:/data

Installation steps

  1. Give the Samsung Frame TV a stable LAN address through a DHCP reservation or equivalent router setting.
  2. Replace 192.168.1.150 with that address.
  3. Run docker compose up -d.
  4. When the TV shows an Allow/Deny prompt for “Frame Art Manager,” choose Allow with the remote.
  5. Place .jpg, .jpeg, or .png files in data/artwork.

Which data must be persistent?

PathPurposeWhy persistence matters
/data/artworkDesired artwork collection and its private manifestIt is the durable source of truth for synchronization.
/data/tokensPairing tokens and per-TV reconciliation stateLosing it can require pairing again and removes ownership evidence.

Mounting the complete /data directory, as in the example, preserves both locations across container upgrades.

Does Docker need host networking?

The documented minimal setup publishes the health and upload port normally and connects to a known TV IP address. The container must be able to reach the television on the local network. Network isolation, VLANs, or firewall rules must permit that connection.

Running on Synology, Unraid, or another NAS

A NAS is suitable when it can run the container and reach the TV’s LAN address. Preserve the data mount and ensure the container account can write to it. If bind-mount ownership is a problem, pre-create data/artwork and data/tokens, then use the documented PUID/PGID or rootless-container approach.

Monitoring the container

The service exposes /live for process liveness, /ready and /health for readiness after a successful cycle, and /status for current and per-TV synchronization information. The container healthcheck uses the application’s own healthcheck command.

Safe configuration for a first run

Set DRY_RUN=true when you want to observe the collection and TV plan without persistent local mutation, pairing, uploads, deletions, or display changes. Keep REMOVE_UNKNOWN_IMAGES=false unless you deliberately want the manager to remove TV artwork it does not own.
